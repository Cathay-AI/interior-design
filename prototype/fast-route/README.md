# 快速找風格原型（fast-route）

目標：讓人在一分鐘內看到喜歡的風格變成 3D；補上自己家的條件後，3D、估價、施工圖和法規評估都跟著貼近他家。四個畫面，唯一的表單是選填的。

| # | 畫面 | 做什麼 |
|---|------|--------|
| 1 | 滑卡 | 一次一張 Pinterest 靈感圖，右滑喜歡、左滑跳過（拖曳、✕／♥ 按鈕、方向鍵都行）。共 18 張、每種風格 3 張；隨時可以直接看 3D |
| 2 | 我家的條件 | 選填：按麥克風用說的或打一句話（「長五米六、寬四米七，中古屋」），聽得出來的欄位自動填好；也可手填坪數、長寬、天花板高、屋況，以及上傳格局圖／平面圖／機電圖（圖片或 PDF）。上方的「掌握度」隨填寫內容上升；可直接跳過 |
| 3 | 3D 成品 | 依滑卡結果生成即時 3D 房間，大小依填的長寬高（或坪數）：拖曳旋轉、A／B／C 視角、換風格、改細節（每次修改存成新版本） |
| 4 | 估價與施工圖 | 依設計逐項估算花費（不問預算），區間依掌握度收窄；六張施工圖預設模糊，模擬付款後才清晰可放大 |

RWD：820px 以下單欄、主要按鈕貼底。

## 掌握度：給得越多，越貼近你家

`lib/context.js` 的 `contextScore` 把屋主補的條件換成 0–100% 的掌握度：長寬 30%（只給坪數 20%）、天花板高 10%、屋況 10%、樓層與隔間 10%、格局／平面圖 25%、機電圖 15%。它會影響四件事：

- **估價**：`tighten` 讓每個工項的區間以中點為準收窄，掌握度滿分時寬度減半。
- **施工圖**：依實際長寬高重新配置（見下），否則依坪數換算的尺寸。
- **3D 房間**：`lib/layout.js` 的 `roomSize` 決定房間大小，客戶家多大就畫多大（百坪也照畫；只有小於 2 公尺放不下沙發、或大於 60 公尺時才取最接近的值並在畫面說明），`roomLayout` 讓家具靠著所屬的牆重新擺放：家具本身不放大，小房間沙發變兩人座、放不下的單椅、茶几、邊櫃、盆栽會自動拿掉。
- **施工前要確認的事**：附了圖面的項目從「待補資料」變成「待判讀」，但不會變成「已檢查」。

語音用瀏覽器內建的語音辨識（Chrome、Safari 支援；不支援時改打字），`lib/intake.js` 的 `parseHome` 會處理「八坪」「五米六」「280 公分」這類口語。

目前的限制：上傳的檔案只留在瀏覽器（`lib/docs.js` 只做分類與檢查），不會上傳也不會判讀內容；3D 只跟著長寬高改變大小，隔間、門窗位置仍是固定的示意格局。

## 估價：看設計，不問預算

`lib/estimate.js` 的 `designEstimate(cond, look)` 依這個設計實際用到的東西列出工項：地坪（木地板或礦物塗料）、牆面、收納櫃（木皮或烤漆）、燈具電工、窗簾、家具軟裝（布、絨、皮），中古屋與老屋再加基礎工程。在 3D 頁改設計，金額會跟著變。沒說坪數就用預設 8 坪並標示「預設」，在估價頁可以直接調。

單價是台灣參考行情的量級，尚未以實際單價表校正；用來看量級，不是報價。

## 施工圖：跟著這個家的尺寸畫，專業覆核後定案

`lib/drawings.js` 用和 3D 同一份配置（`roomSize` → `roomLayout`）產生六張 SVG：平面配置、天花板燈具、插座與弱電、收納櫃立面、地坪計畫、估價明細表。

- **不是同一張範本換數字**：牆、窗、櫃、家具、嵌燈格點（約每 2.2 公尺一盞）、插座位置都依實際尺寸重新配置；小空間會少掉放不下的家具。
- **標準比例**：以 A3 橫式為準，自動選放得下的最大標準比例（1:20、1:30、1:50、1:100…）。
- **定位是草稿**：每張圖標示「草稿・待設計師與施工團隊覆核後方可作為施工依據」。流程是解鎖 → 專業團隊覆核 → 定案。
- **沒有這個家的資料就不賣**：沒給長寬也沒附平面圖時，顯示為「施工圖範例」，不提供解鎖，只請使用者先補資料（`aboutThisHome`）。

模糊是 CSS 效果、付款為模擬，原型階段沒有做圖檔保護。圖框、圖例、線型還不是任何一家事務所的制式圖框；要當成正式出圖格式，需要設計團隊提供圖框與製圖標準。

## 法規與施工條件評估

`lib/rules.js` 依「建物總樓層」和「會不會動隔間／增設廁所浴室」產生提醒，每一項都附依據：

| 項目 | 判斷 | 依據 |
|---|---|---|
| 室內裝修許可 | 六層以上集合住宅需申請；五層以下在增設廁所浴室或動隔間時需申請 | 建築物室內裝修管理辦法 |
| 裝修材料耐燃等級 | 天花板、牆面與做到頂的櫃體需用具耐燃等級證明的材料 | 建築技術規則建築設計施工編第 88 條 |
| 防焰窗簾與地毯 | 地面十一層以上建築需用附防焰標示的產品 | 消防法第 11 條 |
| 撒水頭與火警設備 | 十一層以上：撒水頭下方 45 公分、水平 30 公分內不得有障礙物，高櫃與天花板需現場確認 | 各類場所消防安全設備設置標準 |
| 住宅用火災警報器 | 未達十一層的住宅：天花板重做時保留或補裝 | 消防法第 6 條 |
| 避難與防火區劃 | 不封陽台與逃生通道、不動防火門、維持防火填塞 | 建築技術規則、公寓大廈管理條例 |

狀態有六種：已檢查、衝突、待補資料、待判讀、需辦理、不適用。沒給樓層時一律是「待補資料」，不猜；法規類項目不會被標成「已檢查」。

**這份規則是初稿。** 條號、門檻（六層、十一層、45／30 公分）和例外情形是依現行法規整理的摘要，上線前必須由消防與室內裝修專業逐條核對，並隨修法更新。畫面上也寫明這是提醒、不是合格判定。

## 進度、下載與隱私

- **進度存在瀏覽器**（`lib/persist.js`，localStorage）：重新整理不會從頭來；「重新開始」會清掉。上傳的檔案不存，還原後會提醒重新附上。沒有帳號。
- **分享連結**：3D 頁與估價頁的「複製分享連結」把風格、修改與條件編進網址（`toShare`／`fromShare`，不需要伺服器）；對方打開直接看到同一個設計與估價。不含上傳的檔案與解鎖狀態，內容經白名單檢查。
- **解鎖後可下載**：每張圖可在放大檢視時下載 SVG（檔名如 `A-01-floor-plan.svg`）。
- **麥克風說明**：語音鈕旁有一行說明聲音由瀏覽器的語音辨識服務處理、可能傳到瀏覽器供應商。原型沒有帳號與後端，暫不放隱私權政策與服務條款頁；開始蒐集個人資料或實際收費前需要補上法務審閱過的版本。
- **載入順序**：滑卡頁只載卡片圖；3D 程式與家具模型等使用者到「我家的條件」才開始下載。第一張卡片圖在 HTML 就預先載入。本機以 Lighthouse（手機模擬）量建置後的首頁：效能 95、無障礙 100、最佳實務 100，LCP 2.7 秒，首頁約 950KB。

## 滑卡的圖：Pinterest

`lib/pins.js` 列出 48 張圖（六種風格各 8 張），是從 Pinterest 的公開主題頁挑出來的；滑卡用前 18 張。圖片直接連到 Pinterest 的圖片主機，不存進這個 repo；每張卡片有「來源」連回原頁。

**版權屬於原作者。** 這樣用適合原型展示；正式上線前要換成有授權的圖庫或自製（例如 AI 生成）的圖，只需要改 `lib/pins.js`。

## 3D：好看，但不耗資源

- **場景**（`lib/scene.js`）：單椅、茶几、邊櫃、邊几、吊燈、盆栽、花瓶是 Poly Haven 的真實掃描模型，地板、牆面、木皮、布料、皮革是真實材質貼圖，依風格換組合並染成該風格的顏色（CC0，見 `assets/CREDITS.md`）。沙發、收納牆、窗與紗簾仍是程式建的。素材依風格按需載入（每種風格約 2–4MB），載不到時退回全程式建的版本。
- **光**：一張 100KB 的室內 HDRI（CC0）做反射與環境光，陽光從真的窗洞照進來。
- **需求式渲染**：沒有動畫迴圈。相機或設計改變才畫一格；靜止時 GPU 不工作（e2e 會驗證靜止時 frame 數不變）。
- **拖曳時降解析度、直接畫**；停手 240ms 後才補上抗鋸齒與環境光遮蔽（GTAO）。
- **陰影只算一次**；離開畫面就釋放所有資源。Three.js 延後載入，首頁不用付這個成本。
- 不支援 WebGL 的裝置改顯示示意圖。

## 結構

- `lib/`：除了 `scene.js`、`room3d.js` 之外都是純函式，不碰 DOM，各有單元測試。
  - `taste.js`：風格資料與滑卡計分（`applySwipe`、`pickStyle`）。
  - `estimate.js`：依設計估價。`drawings.js`：施工圖。`layout.js`：空間與家具尺寸。
  - `rules.js`：施工前要確認的事（四態）。`render-scheduler.js`：需求式渲染排程。
  - `pins.js`：滑卡的圖與來源。
  - `context.js`：掌握度與區間收窄。`docs.js`：上傳檔案的分類、檢查與摘要。
  - `persist.js`：進度的存檔與還原。
  - `intake.js`：一句話（語音或打字）→ 坪數、長寬高、屋況（`parseHome`）。
  - `art.js`：WebGL 不可用時的示意圖與吉祥物。
- `vendor/`：Three.js r180 與用到的 addon（MIT，見 `vendor/THREE-LICENSE`）。
- `assets/env/apartment.exr`：Poly Haven 的室內 HDRI（CC0），取自 npm 套件 `@pmndrs/assets`。
- `tools/`：`fetch_assets.py` 重新下載並縮小 Poly Haven 素材；`room.html` 是單看 3D 房間的開發頁。不會部署。
- `app.js`：狀態、四個畫面的渲染。
