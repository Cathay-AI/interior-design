# 快速找風格原型（fast-route）

只做「快速找風格」這一條路線：五個畫面，從一句話到一個家。對應簡報「04 產品體驗・畫面故事板」。

| # | 畫面 | 做什麼 |
|---|------|--------|
| 1 | 新提案 | 按住說話或打字，逐字稿可編輯 |
| 2 | 參考圖 | 點選示意圖，或從相簿／相機放自己的圖（只在瀏覽器預覽） |
| 3 | 我理解的需求 | 列出聽懂的空間、風格、預算；缺坪數時標「請補充」，只問必要的 |
| 4 | 3D 提案 | 可拖曳旋轉、A／B／C 視角；每次修改存成新版本 |
| 5 | 預算與限制 | 預算區間與依據、四態限制（已檢查／衝突／待補資料／不適用）、解鎖更多方案 |

RWD：手機寬度時整頁就是手機畫面；900px 以上顯示手機外框與左側步驟。

## 執行

```sh
npm run dev      # http://localhost:5173
npm test         # 單元測試（node:test）
node e2e/flow.e2e.mjs http://127.0.0.1:5173/   # 需要 playwright
```

## 結構

- `lib/`：純函式，不碰 DOM，各有單元測試。
  - `intake.js`：逐字稿 → 空間／坪數／預算／屋況；`inferStyle` 猜風格，猜不到回 `null`。
  - `estimate.js`：坪數 × 屋況單價 → 預算區間；沒有坪數回 `null`（顯示「暫無可靠估算」）。
  - `rules.js`：限制檢查，每項恰好落在四態之一。
  - `taste.js`：風格資料（看屋二選一的口味引擎目前未接到畫面）。
  - `room3d.js`、`art.js`：CSS 3D 房間與插圖。
- `app.js`：狀態、五個畫面的渲染、語音與檔案等瀏覽器 API。
