# 快速找風格・可玩原型

依產品設計簡報（`docs/proposal/product-design`，A 入口與 B／E 關卡）以及主簡報 p.14–15 的手機畫面故事板，做出一條可以從頭走到尾的路線：

**序章選路線 → 看屋（二選一） → 口味圖譜 → 佈置（選方向、鎖定與重抽、只改牆色） → 定案卡 → 確認需求（語音／文字） → 3D 提案＋粗略報價＋台灣條件檢查**

「我已經有想法」路線也可走（參考圖 → 確認口味 → 佈置 → 定案）；「完整闖關」標示為下一版。

> 原型示意：圖片、名稱與金額都是示意，不是實際產品或報價。尚未做使用者驗證。

## 怎麼跑

```sh
cd prototype/fast-route
python3 -m http.server 5173   # ES modules 需要用 http 開，不能直接雙擊檔案
npm test                      # 單元測試（node:test，不用安裝套件）
node e2e/flow.e2e.mjs http://127.0.0.1:5173/   # 端對端測試（需要 Playwright）
```

## 設計決定

- **邏輯和畫面分開。** `lib/` 是純函式（口味計分、方向、估價、規則、需求解析），有單元測試；`app.js` 只管狀態與畫面。之後換成 JEV 或後端時，只要維持 `lib/` 的介面。
- **不用框架、不用建置。** 原型要能在任何靜態主機上直接開；有需要再換。
- **未知就說未知。** 缺坪數時回傳 `null` 並顯示「暫無可靠估算」；規則只回四種狀態，未知標「待補資料」，不當成通過。
- **用語跟 `docs/agents/domain.md` 一致**：Intake、3D 提案、粗略報價、Rule finding、Revision。

## 測試

- `test/*.test.mjs`：看屋計分、口味圖譜、三個方向、估價與預算比對、四態規則、逐字稿解析。
- `e2e/flow.e2e.mjs`：桌機與手機寬度各走完快速路線一次，檢查估價數字、版本產生，以及沒有水平捲動。

## 可以拆成的 issue（建議）

1. 看屋改用真實圖庫（需授權）並加左右滑卡。
2. 口味圖譜換成基準模型，對照 JEV（簡報 p.16–17）。
3. 3D 改用 GLB 與命名物件，語音修改呼叫工具改參數。
4. 粗略報價接人工確認的費率表與工項。
5. 台灣條件改為有來源、版本與適用條件的規則檢查。
