我們要讓屋主直接表達想像，在手機看懂空間、修改方案，再帶著有依據的資料與專業夥伴接軌。

## A 願景很大，第一站很具體 {span=2 meta="WHY / WHAT"}
```callout info 先完成一個真實空間的閉環
把需求變成可檢視、可修改、可交接的方案。
用實際回饋決定下一步，逐步自動化設計工作。
```
Mika 或 Victor 想換木地板、增加收納。
圖片說得出喜好，工程仍需要尺寸與規格。
我們把這段距離變成一條連續的服務流程。

**第一版：** 單一房間、既有格局、有限材料。
**長期：** 逐工項銜接可施工的圖面與交付。

## B 使用者與證據 {meta="WHO / GOAL"}
```kv
屋主: Mika、Victor
經驗回饋: Chris
專業資源: Even、Josh
核心起點: Victor 的既有 skill
```
**首輪目標：** 兩位屋主完成一次方案修改。
至少一位專業夥伴讀取交接包並提出回饋。
這是內部試點，市場與付費意願仍待驗證。

## C 從想像到接手：同一個空間，持續推進 {span=3 meta="USER JOURNEY"}
```flow LR
屋主想像 -> Skill 空間方案: 需求與尺寸
Skill 空間方案 -> *手機 3D 工作台: 模型與圖面
手機 3D 工作台 -> 修改與比較: 保存版本
修改與比較 -> 專業交接: 材料與待決事項
```
**文字可以啟動設計；尺寸與來源決定能用到哪一步。**
第一輪允許人工協助生成。修改後維持模型、圖面與用量的版本一致。

## D 五個人，一起把服務接起來 {span=2 meta="TEAM / OWNERSHIP"}
| 成員 | 初版主責 | 同時扮演 |
|---|---|---|
| Mika | 屋主體驗、手機介面、3D 互動 | 首位客戶、使用者驗收 |
| Chris | 平台架構、服務與任務流程 | 裝修經驗、部署規劃 |
| Even | 材料估算、工班需求、成本 | 專業資源、部署規劃 |
| Josh | 圖面交接、專業回饋、交付完整性 | 設計師與工班資源 |
| Victor | Skill 整合、需求、使用者驗收 | 首位客戶、部署與網域 |
**全員都可開發，主責可以調整。**
Victor、Even、Chris 共同研究部署、成本與網域。

## E 平台承接能力，手機輕量呈現 {meta="PLATFORM"}
```flow TB
手機與桌機 -> Web 專案服務
Web 專案服務 -> 版本與產物
Web 專案服務 -> 背景生成任務
背景生成任務 -> Skill 引擎
Skill 引擎 -> 版本與產物
```
先看預覽，點選才載入 3D。
以 GLB 與觸控操作起步，靜止時停止重繪。
不支援 3D 時仍可看平面圖與 PDF。

## F 用成果前進，不用空白日期催進度 {span=3 meta="MILESTONES"}
```timeline h
*M0 | 方向與基準 | 案例、交接需求、部署選項
M1 | 上線可看 | 手機 3D、圖面與權限
M2 | 可以修改 | 一次修改與版本比較
M3 | 可以交接 | 材料預估、詢價範圍
M4 | 真實試點 | 屋主、專業與成本回饋
M5 | 施工標準探索 | 限定工項、證據與責任
```
**M5 依 M4 的證據決定投入。** 不先承諾全屋、全自動施工圖。

## G 差異化要靠交接證據累積 {span=2 meta="WHY US"}
| 能力 | 我們想解決的事 | 狀態 |
|---|---|---|
| 生圖、聊天、3D | 讓屋主看懂與操作 | 基本能力，已有競品 |
| Skill ＋平台 | 一般屋主能使用既有生成能力 | 待整合 |
| 同版模型、圖面與用量 | 修改後仍可追溯 | MVP 目標 |
| 在地材料與專業回饋 | 讓方案更容易被接手 | 待案例累積 |
**先以 B2C 工具吸引屋主。**
驗證方案整理、審核或諮詢是否有人願意付費。
價格、施工收入與合作抽成尚未決定。

## H 怎樣才算能拿去施工？ {meta="DELIVERY GATES"}
```timeline v
概念 | 看懂與比較 | 保留假設
協調 | 專業者能回答問題 | 圖面與缺口可追溯
詢價 | 範圍與數量有依據 | 列出排除與暫估
施工發行 | 只針對確認範圍 | 現場、產品與工種確認
```
平面圖是交付的一部分。
自動檢查通過，不代表完成施工審核。
