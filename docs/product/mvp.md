# MVP 規格 v0.2

日期：2026-11-05。使用者最新指示取代 v0.1「以 Victor skill 產物與專業交接為主線」的定位。此文件是產品規劃，不代表功能已實作。

## Problem Statement

屋主有裝修想像與參考圖片，但不想先學繪圖或填一整套專業表單。他希望在手機或電腦快速看見空間效果與大約費用，同時少走不符合實際空間及台灣裝修條件的彎路。

## Solution

**語音或文字＋參考圖片 → 確認簡短需求 → 3D 空間提案＋粗略報價 → 視需要付費解鎖。**

手機優先，電腦也可用。可先沒有平面圖；必要時補充房間用途、面積／關鍵尺寸、地區與預算等少量資訊。從單一房間、有限工項試點起步，精確範圍由 M0 確認。

台灣法規、消防、機電與物理空間是生成與檢查的考量；首版只啟用有依據、可驗證的有限檢查，不宣稱全面法規符合。沒有尺寸的視覺方案仍可呈現，但幾何、預算及規則判讀需保留假設或待確認狀態。

## Confirmed / open

| 已確認方向 | 尚待驗證的選擇 |
|---|---|
| 語音／文字、參考圖片為輸入 | STT／生成供應商、模型與 3D 呈現形式 |
| 基本成果是 3D 與粗略報價 | 額度、費率、首版估價工項及精度 |
| 進階功能付費 | 付費解鎖組合、單次或訂閱、付款供應商 |
| 手機方便，電腦也能用；render 輕量 | 代表裝置、模型大小及效能校準 |
| 主打台灣工程法規／消防／機電／空間考量 | 首批規則、適用情境與專業覆核方式 |
| 有客戶案例的產品構想 | 真實案例來源、同意、隱私與審核 |
| 不綁定 Victor skill | 技術採購與 adapter 方案皆未選定 |

## User Stories

1. 作為屋主，我想用語音說需求，免去手機長篇輸入。
2. 作為屋主，我想修改語音轉成的文字，避免辨識錯誤影響設計。
3. 作為屋主，我想直接打字並加入相簿或相機圖片，表達風格。
4. 作為屋主，我想先確認系統理解的需求，只補必要資料。
5. 作為屋主，我想看到 3D 空間提案，理解預期效果。
6. 作為屋主，我想看到粗略費用區間與主要假設，判斷是否值得繼續。
7. 作為屋主，我想知道影響方案的空間／法規／消防／機電限制與未知事項。
8. 作為屋主，我想在手機與電腦都方便檢視、保存自己的方案。
9. 作為屋主，我想先知道付費可解鎖什麼，再決定是否購買。
10. 作為付費使用者，我想在確認付款後取得對應功能，重新整理後仍保留權益。
11. 作為潛在客戶，我想看有來源、同意展示的案例，了解服務能幫我做到什麼。
12. 作為團隊，我想替換生成引擎與知識來源，而不改掉屋主的使用流程。

## MVP acceptance boundary

主要驗收是「輸入需求與參考圖 → 3D 與粗報價 → 了解限制 → 選擇是否升級」。專業交接、施工圖與案件管理不再是免費基本流程的前置條件。

| 情境 | 可觀察的驗收條件 |
|---|---|
| 語音／文字 | 錄音前說明並取得裝置權限；可停止、重錄、編輯逐字稿；拒絕或不支援時可改打字 |
| 參考圖 | 手機相簿／相機與電腦檔案都可選圖、預覽、移除；檔案條件與失敗原因明確 |
| 需求確認 | 看得見已理解的需求與假設；缺少重要尺寸／條件時只追問必要資料 |
| 3D 結果 | 有實際可開啟的 3D 視覺成果；互動模型或多視角展示由選型決定，不能以單張圖片冒充可編輯模型 |
| 輕量呈現 | 先顯示預覽，按需載入較重內容；手機觸控與桌機滑鼠皆可用；失敗有可讀替代 |
| 粗略報價 | 給預算區間、範圍、數量與單價依據、地區／日期、排除項與未知；資料不足時先補資料或標示暫無可靠估算 |
| 在地限制 | 清楚區分已檢查、衝突、待補資料、不適用；未知不等於通過；來源、版本與適用條件可追溯 |
| 付費解鎖 | 付費前看得見功能差異；以測試付款驗證權益，由服務端控管且可重複處理回呼；取消／失敗不誤開權益 |
| 案例 | 可瀏覽案例卡；沒有真實且同意展示的案例時呈現空狀態。概念示意與客戶案例分開標示 |
| 資料保護 | 住宅圖、語音、方案與預算預設私人；是否保存語音及保留期另確認；不預設公開成案例 |

## Free / paid hypotheses

免費基本層：需求輸入、基本 3D 提案、粗略預算區間；免費額度未定，不承諾無限生成。

付費層候選：更多方案／修改、更高畫質、下載與匯出、更細估價、專業諮詢。**以上是候選，不是全數納入首版或已定價。** 安全相關限制與重要未知事項不因未付費而隱藏。一般檢查不是付費後就自動升級成專業認證。

案例頁候選欄位：空間用途、風格、需求、方案圖、預算範圍／日期、服務層級與展示同意。沒有施工證據不得稱為完工案例。

## Implementation Decisions

產品需求先於引擎選擇。輸入、生成、3D 呈現、估價、規則檢查與權益分離；provider 可替換。付款方案未定，先 sandbox 驗證。知識庫是候選入口，原始法規／產品／價格資料仍需版本與來源。詳見 [架構](../engineering/architecture.md) 與 [知識來源](../engineering/taiwan-knowledge.md)。

## Testing Decisions

以同一份屋主需求，在手機與電腦驗收完整基本流程。涵蓋錄音拒絕／轉錄修正、參考圖失敗、生成失敗、缺估價資料、規則不適用／過期、付款取消／重複回呼／權益恢復及案例空狀態。以具尺寸基準的案例核對幾何與計量；不能用效果圖當實測。尚無平台程式與既有測試邊界，以上為測試規劃。

## Success / next decision

首輪目標：Mika、Victor 完成基本流程（團隊合計覆蓋手機與電腦），能說出報價範圍與限制；Even／Josh 邀請專業者覆核首批規則與估價假設；至少一次 sandbox 解鎖通過。觀察付費意願、每案成本與需人工協助的步驟，再收斂首個付費包。

## Out of Scope

全台全類型建築自動法規審查、完整機電設計、結構／施工核准、直接可施工圖、全 BIM、統包媒合、無限制免費生成、指定 Victor skill、虛構客戶或完工成果。這些不作為基本產品上線的必要條件。
