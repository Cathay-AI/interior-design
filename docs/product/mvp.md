# MVP 規格 v0.1

日期：2026-11-05。狀態：高層方向已確認，實作選型與數值門檻為提案，待首輪校準。這份文件不代表已實作。

## Problem Statement

屋主能描述想像，但難以轉成可修改、有尺寸依據、能交給專業者接手的方案。反覆以圖片、聊天與散落檔案溝通，容易失去版本和決策依據。

## Solution

提供手機友善的 Web 服務，接收需求與既有 skill 產物，展示空間、保存修訂、呈現有限材料預估，並匯出可追溯的專業交接包。第一個案例為既有格局的單一房間，優先牆面與地板。確切房間由 Mika／Victor 提供，不將內附虛構案例冒充真實住宅。

## User Stories

1. 作為屋主，我希望用文字與參考圖片說明想像，讓我不必先學會繪圖。
2. 作為屋主，我希望補充既有平面圖與尺寸，讓方案更貼近真實空間。
3. 作為屋主，我希望知道哪些尺寸是假設，讓我能補量關鍵資料。
4. 作為屋主，我希望在手機查看配置與 3D，理解空間關係。
5. 作為屋主，我希望用觸控旋轉、縮放，不需安裝專用軟體。
6. 作為屋主，我希望提出材料修改並比較版本，確認喜好與成本變化。
7. 作為屋主，我希望系統保留原版本，讓修改失敗時仍能回看。
8. 作為屋主，我希望看到材料費的數量、單價來源與缺漏，避免把它誤認成全案報價。
9. 作為專業夥伴，我希望取得同一版本的圖面、規格與待決事項，判斷能否接手。
10. 作為專業夥伴，我希望按工項回報資料缺口，讓屋主知道下一步。
11. 作為維運者，我希望知道任務是否完成、失敗及成本來源，能處理試點問題。
12. 作為使用者，我希望只有獲准的人能開啟私人住宅資料，並能撤銷分享。

## MVP 行為與驗收

主驗收邊界是「使用者完成一次方案閉環」，不是只測內部函式。先以固定虛構案例驗證平台，再以經同意的真實案例驗證服務。

| 情境 | 可觀察的驗收條件 |
|---|---|
| 輸入與需求 | 可保存需求、來源圖與尺寸狀態；無尺寸仍能做概念提案，不能據此宣稱已可施工 |
| 產物接收 | 收到 manifest 與合法附件後可查看；缺檔、雜湊不符及不支援格式有具體錯誤 |
| 手機觀看 | 390px 寬可看配置／圖面；3D 點選後才載入；觸控旋轉／縮放可用；失敗有圖面替代 |
| 一次修改 | 選取支援的材料項目，人工或任務完成重產；新舊版本可比較，原版不覆寫 |
| 版本一致 | 模型、圖面、用量標示所屬版本；任務完成前不把新舊產物混成一包 |
| 材料預估 | 算式、單位、面積依據、損耗、單價來源／日期可追溯；未知價格留空 |
| 分享與交接 | 獲准收件者可看指定版本；下載檔案真實存在；撤銷後不能沿舊網址持續取得檔案 |
| 專業回饋 | 以範圍、圖號、問題、後果、建議負責角色與關閉證據記錄缺口 |

## 首輪成果目標（驗收提案）

- Mika、Victor 各完成一次檢視、提修改、比較版本；觀察需人工協助的步驟，不宣稱已驗證外部市場。
- 至少一位由 Even／Josh 接洽且同意參與的專業夥伴，實際閱讀一份指定版本交接包。
- 用固定尺寸案例人工核算牆地材用量，事先約定扣除及四捨五入規則，再比對系統結果。
- 記錄至少一個代表性手機測試環境、載入時間、失敗情況與改善事項。
- 商業訪談記錄「願付費／不願付費／原因」；真實付款與口頭意願分開。

## Implementation Decisions

先保留現有 skill 的產物契約，透過 adapter 接入；以專案／修訂／產物為核心。長任務離開 Web request 生命週期。效果圖為表現證據，幾何與圖面保留來源版本。首版允許人工執行生成，不把任意自然語言全自動改模列為上線前提。詳見 [架構](../engineering/architecture.md)。

## Testing Decisions

以「匯入 → 手機檢視 → 修改重產 → 比較 → 材料預估 → 分享 → 收到回饋」為最高層驗收。補充缺檔／版本混用／越權存取／失敗任務案例。平台是空 repo，尚無既有測試邊界可重用；上游 demo 僅作 adapter fixture 候選，不能替代平台或專業驗證。測試方式隨技術棧選定，尚未宣稱通過。

## Out of Scope

第一版不承諾全屋自動辨識、拆牆結構判斷、完整 BIM、全自動機電或法規審查、直接施工發行、工班媒合／合約／付款管理、自訓模型、VR 或即時 path tracing。平面圖是交付的一部分，不能取代所有必要立面、剖面、細部與規格。
