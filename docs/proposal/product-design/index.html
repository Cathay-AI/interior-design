底層能力・決策引擎評估

先試 JEV，用基準模型把關

判斷候選它做什麼放到這個產品
先試JEV TypeSafe 的 System One 模型輸入文字或 JSON 狀態，輸出 Choice、Score、Noul 等型別和機率形式很合：輸出分類，速度適合滑卡。但校準和速度都是廠商自述，還沒有獨立評測
對照貝氏 logit 基準模型用二選一資料估計每個人的偏好和不確定性自己掌握、資料少也能跑；用來判斷 JEV 是否真的比較好，也是備援
採用期望價值出題依機率挑最值得問的下一題首版只有 60–100 張圖，可以逐題計算；JEV 或基準模型都能提供機率
之後階層模型用跨使用者資料提供新使用者的初始猜測需要先累積真實資料；官方文件也沒提到 JEV 可以客製訓練
不採用每人訓練小模型只拿個人資料從頭訓練資料太少，容易過擬合，也沒有不確定性可用來出題

採用前要確認JEV 仍在早期存取，服務託管在美國。政策寫明不拿輸入訓練模型，但沒寫 API 輸入的保留期限；也沒看到公開權重，要保留可替換的介面。

參考：TypeSafe 發表文、官方文件、Flavio Copes 指南、隱私政策

底層能力・JEV 放在哪裡

讓 JEV 做判斷，讓程式做計算

適合試的場景輸出作法
需求逐字稿Choice把空間用途、風格整理成分類；坪數和預算用程式解析
風格標籤Noul每個標籤問一題，平行回答，就能多標籤
猜喜不喜歡Noul狀態放選擇紀錄和圖片屬性，輸出喜歡的機率
裝飾密度等屬性Score用 2–10 級描述，幫文字資料分級
商場下一件單品Choice依目前線索，從 255 件以內挑最值得看的單品
分享與生成前檢查Noul檢查留言和提示詞是否安全

不交給 JEV

  • 人格計分、準則對照、家人交集用程式計算；家人取交集，不取平均
  • 報價和面積數字與計算不是它的強項
  • 法規判讀維持有來源的規則檢查
  • 金句和圖片生成它不產生文字或圖片
  • 直接看圖圖片輸入仍是實驗功能，正式環境先用屬性

只傳必要資料不傳姓名、房間照片和預算。無關資料會拉低準確度，文字內容也可能影響判斷，所以留言要當不可信輸入。

參考：TypeSafe 發表文、官方文件、Flavio Copes 指南、隱私政策

收尾・開發順序與驗證

先做可玩原型，驗證了再擴大

  1. 1

    闖關有幫助嗎？

    同一批圖，比較闖關版和純滑卡版的完成度與理解度。

  2. 2

    人格卡說得中嗎？

    會不會覺得「這就是我」、願不願意分享；推出的準則是否合用。

  3. 3

    家人真的會來測嗎？

    邀請送出後有多少人完成，結果有沒有引發實際討論。

  4. 4

    JEV 猜得中嗎？

    留出圖的準確度和校準度，要贏過基準模型和「推最熱門」，並實測台灣的延遲。

  5. 5

    商場值得做嗎？

    有商場和沒商場，比較風格收斂的程度與選擇信心。

  6. 6

    結果比較好嗎？

    盲測：依口味生成的方案，對上通用方案。
